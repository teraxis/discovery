# /discovery — NotebookLM через скрипт

Мета — мінімум токенів. Ти лише складаєш одну команду й запускаєш її. Скрипт робить усе сам і друкує 3–8 рядків підсумку. **Не читай** результати (DOCX, answers.json, журнали), якщо користувач прямо не попросив. Передай йому підсумок і шлях до файлу.

`<SKILL>` нижче означає теку, у якій лежить цей SKILL.md. Команда:
- Windows (PowerShell): `& "<SKILL>\nlm.cmd" <команда> …`
- macOS / Linux: `"<SKILL>/nlm" <команда> …`

## 0. Перший запуск
Якщо команда повертає код 9 або «Not installed» / «Не встановлено», виконай `AGENT_SETUP.md` з кореня репозиторію (або з `<SKILL>/../../AGENT_SETUP.md`). Коротко:
1. Встанови: `powershell -ExecutionPolicy Bypass -File "<SKILL>\install.ps1"` (або `sh "<SKILL>/install.sh"`).
2. Попроси користувача виконати `nlm login` у своєму терміналі. Вхід у Google робить тільки людина, ти пароль не вводиш.
3. Запусти `nlm doctor` і передай підсумок.

## 1. Вибір типу дослідження
1. Якщо користувач не назвав тип і він не очевидний з запиту, виконай `nlm types` і запропонуй вибір одним коротким питанням.
2. Якщо тип зрозумілий, одразу запускай:
   ```
   nlm start ТИП --materials "ТЕКА_або_ФАЙЛ_або_URL" [--materials …] --out "ТЕКА_РЕЗУЛЬТАТУ" [--var "КЛЮЧ=значення"] [--notebook "Назва"]
   ```
   - Параметри, позначені `*` у `nlm types`, обов'язкові. Якщо такого параметра бракує, спитай користувача, не вгадуй.
   - `--materials` приймає локальну теку, бо OneDrive довантажує хмарні файли сам. Також підходить тека Drive for Desktop (`G:\Мій диск\…`), файл, URL або посилання на теку Google Drive. Для посилання на теку потрібен `nlm drive-auth`.
   - Скрипт обходить підтеки рекурсивно й завантажує лише формати, які підтримує NotebookLM. Файли xlsx/xls/html він конвертує в Markdown, а тимчасові копії видаляє.
3. Вбудовані типи:
   - `oglyad` — огляд матеріалів;
   - `pytannia` — відповіді на перелік питань;
   - `research` — Deep Research в інтернеті;
   - `kandydat` — аналіз доброчесності кандидата, параметр `ПІБ`; скорочена форма `nlm kandydat --pib … --materials … --out-dir …`.

## 2. Довільний запит → `quick`
```
nlm quick --notebook "Назва" [--folder ТЕКА]… [--file Ф]… [--url U]… [--drive FILE_ID]…
  [--persona ПРОМПТ] [--length longer] [--var "К=З"] [--ask "питання або назва промпту"]…
  [--ask-file питання.txt] [--research "запит"]… [--explore 5] [--report ПРОМПТ]
  [--out ТЕКА_або_файл.docx] [--template бланк.docx] [--citations list|quotes|none] [--dry-run]
```

## 3. Промпти й власні типи
- `nlm prompts` показує список промптів з ознакою `persona`/`ask` і кількістю символів. Ліміт persona становить 10 000 символів, скрипт перевіряє його сам.
- `nlm prompts add НАЗВА --file текст.md [--use persona|ask|report] [--description …]` додає власний промпт.
- `nlm prompts import документ.docx` ділить документ на промпти за заголовками.
- `nlm types add "Назва" [--from oglyad]` створює власний тип: копію шаблону в теці користувача. Скажи користувачу, який файл редагувати.
- Власні промпти й типи з тією самою назвою мають перевагу над вбудованими.

## Правила
- Повторний запуск безпечний: уже завантажені джерела скрипт пропускає.
- Якщо запит неоднозначний, спершу виконай `--dry-run`. Він показує план без змін.
- Код 2 з текстом «Немає входу» означає, що вхід виконує людина. Передай їй `nlm login`.
- Рядки, що починаються з `!`, означають помилки. Подивись лише кінець файлу `log.txt` з теки, яку вказано в підсумку.
- Не запускай завдання паралельно для одного й того самого блокнота.
